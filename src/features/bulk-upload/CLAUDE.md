# P27 · Bulk upload (emission rows)

> Blueprint spec. Route `/capture/upload` (alias `/upload-data`) for Superadmin; the same `BulkUploadStepper` opens from P03 for contributors (scoped to their site/category).
> Replaces `pages/UploadPage.tsx` (legacy import, shows default password in plain text) and `pages/BulkUpload/*` (FileUploadStage, ColumnMappingStage, ReviewStage, UseBulkUpload). AI service: `/v1/excel/upload → unique-categories → preview → import`.

## Stepper
1. **Upload** — Client* and Site* (Superadmin) or prefilled (contributor); Category (or "from the sheet"); FileDrop `.xlsx/.xls/.csv`; **Download template**; tips.
2. **Map columns** — required field → sheet column, auto-matched with "Matched"/"Check" chips, Skip toggle; category list loads automatically (no separate "Load categories" click); select categories to import.
3. **Preview** — first 100 rows with Global category, Factor, Unit, tCO₂e, Issue column; filter by issue; counts Valid/Issues.
4. **Import** — progress bar; result stays on screen (no auto-close) with imported/skipped and downloadable skipped-rows CSV; link to P07 Upload batches (rows arrive as **pending**).

## Legacy import (Superadmin only, behind "Historical import")
Keep the year/month/equipment… format but: pick existing site/category only (no free-text creation that bypasses master data), require client, preview before import, and **never display passwords**; created users get invite emails.

## Rules
Closable while busy with "continue in background" (import keeps running; toast when done).

## As built
- Part 1 (FE #116, with python_AI_service #21): the four-step stepper, context in the URL (`?client=&site=&category=&period=`). The per-row date key is `date_of_reporting`. There is no "category from the sheet" option, because the AI service needs one category_id.
- Part 2 (with ESG-lite #83, stacked on #79):
  - **Historical import** is at `?mode=historical`. It posts to `POST /admin/upload/emissions` with `companyId`, `siteId` and `categoryId`, previewing by default and saving only with `commit=true`. Months already filed, repeated months and rows with no total are skipped with a reason. New people get an invite through #79's `issueInvite`, and the result shows a warning when email isn't configured.
  - **Contributors:** the route also allows `User`. A contributor sees only their own sites (from the signed-in user, without FERA), has no client picker and no historical import, and reads the form through `/user/column-configs`. Add data links to `/capture/upload?site=&category=&period=`, using the month the entry period ends. This is a link to the same page, so nothing had to move to `src/ui`.
  - **Legacy files:** `pages/UploadPage.tsx` and `pages/BulkUpload/*` are kept until the PR that turns the new UI on, following the P03 and P24 precedent. With the flag off, `/upload-data` and the classic Add data modal still use them. With the flag on, `/upload-data` already redirects to `/capture/upload` (routeMap).

## As built (IM11, with python_AI_service #25)
Spec: ESG-lite `docs/mcp-import/later/IM11-bulk-upload-on-plans/CLAUDE.md`. The page keeps its four steps; Preview and Import now read ESG-lite's plan instead of the Python calculation, so a sheet row and a typed entry are the same code (IM1 engine behind the IM2 plans API, channel `bulk_upload`).
- **Preview** (`usePreview`, `fetchPreviewRows`): one call plans the whole sheet and answers `{ plan, rows, total_rows, not_selected, sheet_rows }`. `plan` is the IM0 `ImportPlan` without rows (`PlanSummary` in `excelService.ts`): the KPI strip shows its `counts.ready`, `counts.issue + skipped` and `totals.tco2e` for the whole sheet; the table shows the first 100 rows with the factor used (and its year), value, unit, tCO₂e, FERA tCO₂e (hidden by default) and the Issue column. `rowIssue` reads the row's `state`: `issue`/`skipped` rows are "Won't import" (red, `row_error` = the engine's messages), a `row_warning` imports as shown (amber). There are no "saved as 0 tCO₂e" rows any more: no factor or a zero total is an issue the engine refuses. The page keeps the last plan's id in a ref and sends it as `cancel_plan_id` on the next preview, so re-mapping doesn't pile up drafts (ESG-lite allows ten per user); it is cleared after an import or "Start another upload".
- **Import** (`useImportRows`, `importAllRows`): sends `plan_id` + `version` from the preview (no `user_id`; ESG-lite knows the caller from the token). The button says `Import N rows` with N = `counts.ready`, and is off when the plan has no id (every row refused before planning) or nothing is ready. The result keeps `inserted`, `skipped`, `skipped_rows` (row number, category, the engine's reason), `fera_inserted` (shown as a hint under Imported) and `upload_batch_id`.
- **Errors:** the AI service passes ESG-lite's status and IM0 body on under `detail`; `ExcelServiceError` carries `status` and `code`. A `409 IMPORT_PLAN_VERSION_CONFLICT` (rows changed between preview and commit) shows as `PLAN_CHANGED_MESSAGE`; "Back to preview" after any failed import previews afresh (a new plan, the old one cancelled). The document-claim 409 (file already imported) keeps its old string message.
- **Mapping:** the value field can't be skipped any more (`canSkip`): ESG-lite refuses a row with no value and no fields, where the old service guessed a value from any number column. Multi-field forms still have no value field.
- Tests: `logic.test.ts` (issues by state, counts from the plan, value not skippable, skipped rows with their row number) and `e2e/bulk-upload.spec.ts` (preview body, plan KPIs, issue filter, import body with `plan_id` and `version`, skipped-row line).

## Smart import (XI4, plan `docs/excel-import/` in ESG-lite, copied from `/mnt/project-files/excel-import/modules/XI4-smart-import-flow/CLAUDE.md`)

> Depends on XI0 (ESG-lite #121, merged). Lane L3. Two PRs: 1/2 route, switch and screens on a mocked proposal; 2/2 wired to `/v1/excel/propose` and mapping profiles once XI2 (python) and XI3 (ESG-lite) merge.

### Outcome
A Manager opens Bulk upload, drops any workbook, sees what the app worked out, fixes what it got wrong, reviews the planned rows, commits, and lands in Review rows. Superadmin and Admin get the same flow; User keeps the prefilled contributor path.

### Screens (same stepper shell as P27, `?mode=smart` is the default when `ai_import_enabled`)
1. **Upload**: Site picker (one of the caller's sites, required; prefilled when the caller holds one site) and FileDrop; no category picker (categories come from the sheet). A line "Rows for other sites will be skipped; upload the file again for each site." When the client switch is off, the old one-site-one-category stepper shows with a note Superadmin can turn Smart import on (P17 client detail switch, added in this module).
2. **Confirm mapping**: one card per sheet. Category (fixed or "from column X"); when the sheet has a site column, a line per other site found; period; field → column table with chips Matched / Remembered / Suggested / Check (confidence < 0.8 or empty required field); activity matches table (sheet wording → factor, change / skip, "Save for this client" tick per decision 5); "Last time you mapped this as…" when the source is a profile, with Change. Continue is disabled while any Check chip remains on a required part. Sheets can be excluded.
3. **Review rows**: the plan from `/v1/excel/preview`: rows with factor, unit, tCO₂e, issues; filters by issue code including `SITE_NOT_ALLOWED`; per-row skip and edit (PATCH), "Skip all rows with this issue"; totals by category and month. Rows still in state issue are left out at import (see "Against XI2 as built").
4. **Import**: commit; result shows imported / skipped, a link "Review rows" to Approvals for the batch (P07, Manager only, since Approvals is Manager-only; Admin and Superadmin get "The site's manager approves them") and the note that rows are pending.

### Rules
- Route roles: `bulk-upload` is `["Superadmin", "Admin", "Manager", "User"]`; the API is the gate, the route is cosmetic.
- Everything in `src/ui` tokens, four themes, 390px; no hex, no `isDark`.
- Row issues have a third severity `info` (`PIVOT_EMPTY_CELL`); the issue filter and chips render it.
- Loading, empty (a workbook with no usable sheet) and error (403 `AI_IMPORT_DISABLED_FOR_CLIENT`, rate limit, model unavailable → fall back to the manual mapper, never a dead end) states.

### As built, part 1/2 (mocked proposal)
- Files: `smart/types.ts` (XI0 shapes), `smart/logic.ts` (chips, Continue gating, edits to the proposal, issue filter, copy, errors), `smart/api.ts` (TanStack hooks), `smart/fixtures.ts` (`MOCK_PROPOSAL`, used by `smart/logic.test.ts` and `e2e/smart-import.spec.ts`), `components/smart/*` (SmartUploadStep, ConfirmMappingStep + SheetCard, SmartReviewStep + RowEditModal, SmartImportFlow). `Page.tsx` picks the mode; `ImportStep` gained `reviewLink`.
- **Mode** (`?mode=`, part of `useUploadContext`): `smart`, `manual` or `historical`. Default: smart for a Manager or Admin whose client has `ai_import_enabled` (read off `user.sites[].company`, which `/auth/me` returns), smart for a Superadmin once `?client=` names a client with the switch on, manual otherwise. The header action switches; a Superadmin's client change pins `mode=smart` so the choice sticks. A User never sees the mode. With the switch off, a Manager or Admin sees the column mapper under a note that ESGLite staff turn Smart import on per client; a Superadmin who picks such a client sees a callout linking to the client's overview and the Continue button stays off. Nav: Manager Data ▾ and Admin got "Bulk upload".
- **Services** (`excelService.ts`): `proposeMapping` (`POST /v1/excel/propose`, `{ document_id, site_id }`), `fetchSmartPreview` (`POST /v1/excel/preview` with `proposal`, `page`, `page_size`, optional `code`, `plan_id`, `cancel_plan_id`), `importProposal` (`POST /v1/excel/import` with `proposal`, `plan_id`, `version`). `importPlansService.ts` calls ESG-lite directly with the user's token: `patchImportPlan` (`PATCH /imports/plans/:id`, `changes[]` with `set` or `skip`), `getImportPlanPage` (`?code=&page=&page_size=`), `skipRowsWithIssue` (reads every row ref with the code, patches in batches of 2,000, carries the version forward), `searchImportActivities` (`/imports/context/activities`, the factor picker on the activities table).
- **Confirm screen**: a user's pick (another column, factor, category or category value) sets `confidence: 1, source: "rules"` on that part (the enum has no "user"). Confirm keeps the proposed value as is: it sets `confirmed: true` and keeps the part's own confidence and source, so a low-confidence match still shows to the approver under "Needs attention" (Shyam, 2026-10-14); a confirmed part never shows Check. Optional fields can be skipped; required ones not. An activity cleared to no factor is left for the plan to flag (`UNKNOWN_ACTIVITY`) and skipped there. Column options are the upload's `headers` plus every column the sheet's proposal names (`knownColumns`); when XI2 adds `SheetProposal.columns` the picker reads it as is. The spec's "40 rows will be skipped" count per other site isn't in the XI0 contract (`site_column.values` has no count), so the line says "its rows will be skipped".
- **Review screen**: the first preview plans the workbook (cancelling the plan of an earlier preview); once the plan id is known the args switch to paging it (`plan_id`), seeded with the same data. Skip, unskip and edit (activity name, value, unit) patch the plan at its current version and invalidate the preview, which rereads the plan at the new version. The issue filter sends `code` to the preview; when the service pages the whole plan anyway, each page is narrowed to that code and paging stays over the whole plan (a status line says the filter is per page), so every matching row is reachable. Pages are 0-based in DataTable and sent 1-based. Import needs a plan id and `counts.ready > 0`, reads "Import N rows, leave M out" while issue rows remain, and is off (like Skip and Edit) while a change saves or the plan is reread, so every patch and the commit carry the current version. The row edit modal keeps its draft per row.
- **Against XI2 as built** (python_AI_service #36, 2026-10-14): `/v1/excel/import` always commits with `skip_rows_with_issues`, and rows the AI service keeps back as local issues (`SITE_NOT_ALLOWED`, `CATEGORY_NOT_ASSIGNED`, `MISSING_*`, `VALUE_NOT_NUMERIC`) are counted into `counts.issue` but never sent to ESG-lite, so they can't be skipped through `PATCH /imports/plans/:id`. Blocking Import on `counts.issue` would therefore be a dead end on any sheet with another site's rows; the warn callout says those rows are left out instead. `/v1/excel/preview` pages by `state` and (at #36's head) does not pass `code` on to `GET /imports/plans/:id`, hence the client-side narrowing above; "Skip all rows with this issue" reads the refs from ESG-lite directly, so it is unaffected. For a code the AI service kept back (`issues_summary[].local`) ESG-lite has no such rows, so the button is not offered and a line says those rows are left out; their rows offer no Skip or Edit either (`local` on the preview row). Asked of lane 1: pass `code` through.
- **Sites** (review of 2026-10-14): a Manager's smart-mode site list holds only sites of a client with the switch on, and the single-site prefill counts only those. An Admin's list is every site of their client from `/company-admin/sites` (`useCompanySites`, `withClientSites`), carrying the client and switch the session user names; the session user (`/auth/me`, reread on every page load) says whether the switch is on, so a change shows after a reload, not a new sign-in. "Back to bulk upload" from Historical import goes to the client's default mode. A column-category value set to "Not imported" (or confirmed with "Confirm these") clears Check; every value left out keeps it.
- **Until XI2 lands** `/v1/excel/propose` answers 404 on a server: the upload screen shows "The mapper isn't available right now" with "Map the columns yourself", which switches to `?mode=manual`. 403 `AI_IMPORT_DISABLED_FOR_CLIENT`, 429 and other refusals show their message under the file drop.
- **Not in part 1**: `GET /imports/mapping-profiles` ("Last time you mapped this as…" per profile and "Forget this mapping", XI3), `?mode=smart` on the Add data deep link, audit row XI-07.
- Tests: `smart/logic.test.ts` (chips, Continue gating, exclusion, confirm and skip edits, issue options, severity, Review rows link, switch, errors), `e2e/smart-import.spec.ts` (manager path upload → confirm → review → skip other site's rows → commit → Review rows link, with the bodies sent; 390px; switch off; Superadmin per-client switch and manual fallback), `e2e/clients.spec.ts` (the Smart import switch).

### Part 2: mapping memory (XI4 2/2, with ESG-lite XI3)
- **"Last time you mapped this as…"** on a sheet card: once the proposal is on screen the flow reads `GET /imports/mapping-profiles?fingerprint=&site_id=` once per distinct sheet fingerprint (`useMappingProfiles`, the user's own token; a Superadmin adds `company_id` of the chosen client; nothing is read while the client switch is off, since ESG-lite refuses it). `profileFor` picks the profile keyed on the sheet's category (fixed id, or none for a column category), else the newest. The line says what was confirmed (`profileSummary`: category, period, field columns, activity matches) and when (`profileWhenText`: date and uses).
- **Use it** shows only while the card differs from the profile (`profileDiffers` compares category, period, field columns and skips, and the matches of wordings both sides have, key- and order-insensitive, since jsonb reorders keys). `applyProfile` puts the remembered category, period and fields on the card, marked Remembered; activities and column-category values stay this upload's: a wording the profile knows takes its remembered match, a new one keeps its own match and chip, and a wording only the profile knows is not added. What the reader found (rows, header row, site column, names out of scope, Included/Left out) stays. Once XI2 serves profiles itself the card already matches and only Forget shows.
- **Forget this mapping** is `DELETE /imports/mapping-profiles/:id`; the line goes, the card keeps what's on it. A 403 (a Manager who didn't confirm it, or a User) reads "Only the person who confirmed this mapping, or an admin, can forget it." and the button stays; a 404 means it is gone already and the line goes as after a delete. The Forgetting… state and its error belong to the one profile, not every card with the same layout.
- Nothing is written from here: ESG-lite learns the confirmed proposal when the plan commits (python sends it as `mapping` on `POST /imports/plans`, XI2). Changing anything on the card and importing is how a mapping is updated.
- Tests: `logic.test.ts` ("mapping memory"), `e2e/smart-import.spec.ts` (line, Use it, Forget refused then done, Superadmin reads with `company_id`).

### No confirm step when the mapping model is on (Shyam, 2026-10-15)
- "If the mapping model key is turned on, no check should be needed from the user side; show the rows directly for review." When the proposal says the model worked on it (`modelMapped`: `proposal.model.name` set and not `"none"`; python reports `"none"` when `MAPPING_MODEL_PROVIDER`/`ANTHROPIC_API_KEY` leave it on rules only), the flow plans the proposal as the model made it and opens Review rows straight after the upload. The stepper marks Confirm mapping done; Check chips don't block.
- Matches the model was unsure about keep their own confidence and source, so ESG-lite flags them `LOW_CONFIDENCE_MATCH` ("Imports with a note") and the approver sees them under "Needs attention", as with Confirm (2026-10-14 decision).
- Review rows shows "ESGLite mapped this workbook for you" and its Back button reads "Change mapping", which opens the confirm screen with the proposal; continuing from there plans afresh. Mapping memory learns on commit as before (no `confirmed` flag is needed by the learner).
- Rules only (no key): unchanged, the user confirms the mapping first.
- Tests: `logic.test.ts` ("mapping model on"), `e2e/smart-import.spec.ts` (rows straight after upload, Change mapping). `MOCK_PROPOSAL` now reports the model as `"none"`; `MODEL_PROPOSAL` is the same workbook with the model on.
